# Release checklist

1. Run tests and the demo from a clean virtual environment.
2. Confirm `.env`, `.rajih/`, local paths, credentials, and generated outputs are not tracked.
3. Confirm private research materials and their Git history are absent.
4. Verify documentation links and installation commands.
5. Confirm the copyright and custom source-available license text.
6. Push from a clean, independent Git repository.
7. Tag the release and publish a GitHub Release.
8. Do not describe the offline demo as a live provider integration.
